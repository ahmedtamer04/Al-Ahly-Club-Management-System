## 🔄 ROLE-BASED FORM RENDERING

### Frontend Logic

```javascript
┌─────────────────────────────────────────────────────┐
│  IF role === "Vendor"                               │
│    ├─ SHOW: company_name field                     │
│    ├─ SHOW: email field (any email)                │
│    ├─ HIDE: first_name field                       │
│    ├─ HIDE: last_name field                        │
│    ├─ HIDE: id_number field                        │
│    └─ DISABLE: @guc.edu.eg validation              │
│                                                     │
│  ELSE (Student, Staff, TA, Professor)               │
│    ├─ SHOW: first_name field                       │
│    ├─ SHOW: last_name field                        │
│    ├─ SHOW: email field (@guc.edu.eg required)     │
│    ├─ SHOW: id_number field                        │
│    ├─ HIDE: company_name field                     │
│    └─ ENABLE: @guc.edu.eg validation               │
│                                                     │
│  IF role === "Staff" || "TA" || "Professor"        │
│    └─ SHOW: ⚠️ Approval warning message            │
└─────────────────────────────────────────────────────┘
```

## ✅ VALIDATION FLOW

### Registration Validation

```
FRONTEND VALIDATION
├─ Step 1: Password match check
│  └─ password === confirmPassword ❓
│
├─ Step 2: Role-specific checks
│  ├─ IF Vendor:
│  │  └─ company_name filled ❓
│  │
│  └─ IF Non-Vendor:
│     ├─ first_name filled ❓
│     ├─ last_name filled ❓
│     ├─ id_number filled ❓
│     └─ email ends with @guc.edu.eg ❓
│
└─ Step 3: Send to backend
   │
   ↓
BACKEND VALIDATION
├─ Email uniqueness check
├─ ID number uniqueness check (non-vendors)
├─ Email domain check (non-vendors)
├─ Password hashing
└─ User creation with appropriate status
```
